Q1: Does graph structure influence spatial placement order?
A1: NO. Placement uses RandomSeed, not graph traversal order.
    File: LayoutGeneratorStep.cs, Line 36-39
    Proof: RandomSeed is required input
    
Q2: Does room adjacency algorithm try ALL positions?
A2: NO. Uses door matching, retries with new seed (seed + i*1447).
    File: GenerationPipeline.cs, Line 208
    Proof: Each attempt increments seed, doesn't enumerate positions
    
Q3: Can we inspect Room.Position data?
A3: YES. Use layout.Rooms[roomId].Position (Vector2DInt).
    File: RoomNode2D.cs, Line 342
    Access: room.Position.X = row, room.Position.Y = column
    
Q4: Can we validate/reject layouts based on room positions?
A4: YES. Write custom GenerationStep that throws exception.
    File: GenerationStep.cs (base class)
    Flow: If step throws → results.Success=false → retry with new seed
    
Q5: How does RunAttemptsAsync retry work?
A5: Loops up to 10 times (default), incrementing seed by 1447 each attempt.
    File: GenerationPipeline.cs, Line 208
    Formula: seed + i * 1447 (i=0,1,2,...)
    Default: 10 attempts, 5000ms timeout each

================================================================================
COORDINATE SYSTEM
================================================================================

Room.Position = Vector2DInt
  X = Row (0, 1, 2, ...)
  Y = Column (0, 1, 2, ...)

Grid layout (with cells):
  (0,0) (0,1) (0,2) ...
  (1,0) (1,1) (1,2) ...
  (2,0) (2,1) (2,2) ...
  ...

World conversion (CellSize = 96x96):
  WorldX = Position.Y * CellSize.X = Position.Y * 96
  WorldY = Position.X * CellSize.Y = Position.X * 96

Example:
  Position(3, 5) → Row 3, Col 5
  World: (5*96, 3*96) = (480, 288)
